# 修复失败任务自动重试

## 背景

管理员“待人工确认”列表出现失败原因 `upstream request failed; 已转人工确认，请联系客服处理后再试`。该任务来自 Desolate Open 创建订单阶段。

现有 `gpt-api-client.js` 仅把网络异常、HTTP 429 和 HTTP 5xx 识别为可重试。Desolate Open 契约还定义了两个明确的临时业务错误：

- `40011`：上游服务错误
- `40012`：上游服务超时

这两个错误可能通过 HTTP 200 + 非零业务码返回，因此当前逻辑会跳过重试并立即由 `runGptApiWorker` 建立人工审核记录。此外，现有默认值只有 2 次重试、1 秒基础退避，而且缺失的 `Retry-After` 会被 `Number(null)` 错误解释为 0，实际可能无等待地瞬间耗尽重试。

## 目标

短暂上游故障应在当前任务内自动重试；只有连续重试仍失败时，才沿用现有失败处理并进入人工确认。

## 需求

1. Desolate Open 创建订单在以下情况自动重试：
   - 网络异常；
   - HTTP 429；
   - HTTP 5xx；
   - 业务码 `40011`；
   - 业务码 `40012`。
2. 其他业务错误（包括 `40013` 套餐不支持、鉴权/参数/Session/幂等错误）不得自动重试。
3. 所有重试必须复用原请求体、`Idempotency-Key` 和当前请求链路标识，避免重复创建订单。
4. 默认重试策略调整为最多 5 次重试（首次请求之外），基础退避 5 秒，指数增长且单次等待最多 60 秒；继续支持现有配置和环境变量覆盖，并优先遵循上游 `Retry-After`，但等待仍需有界。
5. 自动重试期间任务维持运行状态，不创建人工审核记录、不释放卡密、不回滚卡片；最终恢复后继续正常轮询订单。
6. 重试耗尽后沿用当前失败路径：客户消息保持通用，管理员保留具体诊断，并创建一条人工审核记录。
7. 不自动重跑已经存在的人工审核记录；修复只影响新提交任务。
8. 不新增数据库字段、路由、后台按钮或外部依赖。

## 验收标准

- `40011`/`40012` 后续恢复时，同一任务自动成功创建订单且不产生人工记录。
- `40011`/`40012` 持续失败时，达到上限后只返回一次最终失败，随后才进入现有人工确认逻辑。
- 重试各次请求的幂等键和请求体完全一致。
- `40013` 和普通 4xx/业务错误仍只请求一次。
- 网络异常、429、5xx 的现有重试行为不回退。
- 客户端敏感信息隔离、管理员诊断和人工审核去重语义不变。

## 非目标

- 不修改已存在人工审核记录。
- 不自动解除人工审核。
- 不修改订单轮询终态规则。
- 不部署到 RN，除非用户另行要求。
