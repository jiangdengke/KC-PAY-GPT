# 用卡记录筛选、分页与页面精简

## Goal

精简后台“银行卡池管理”页面，移除顶部统计卡片，并让 Orbitcard 用卡记录在数据量较大时可通过常用条件筛选和服务端分页快速定位卡片。

## What I already know

* 用户要求移除银行卡池管理页面上半部分的统计卡片。
* 用户要求 Orbitcard 用卡记录增加筛选与分页，筛选项由代码现有数据决定。
* 当前页面为原生 HTML/CSS/JavaScript，后端为 Express，数据通过 MySQL store 查询。
* `public/admin.js` 已有 Orbitcard 记录分页参数，但后端只支持全表计数和分页，没有筛选。
* 现有记录字段包含卡 ID、后四位、套餐、使用次数/上限、状态、余额、最近使用时间，以及充值历史中的账号邮箱和订单状态。
* 当前工作树已有与 Orbitcard 卡资料、分页、策略相关的未提交改动，本任务只在其当前基础上继续，避免覆盖其他工作。

## Requirements

* 删除银行卡池管理页面中用于展示卡片统计的上半部分区域；保留银行卡列表、Orbitcard 用卡记录和开卡策略切换区。
* Orbitcard 用卡记录提供服务端分页，默认每页 20 条，并显示当前范围和总数量。
* 提供可由现有字段可靠支持的筛选：关键词（卡 ID/后四位/产品编码/账号邮箱/订单号）、套餐、卡片状态、充值结果状态。
* 筛选条件改变后从第 1 页重新查询；翻页时保留筛选条件。
* 筛选接口使用参数化 SQL，限制页码、页大小和关键词长度，避免把用户输入拼接进 SQL。
* 页面在无结果、加载失败时继续保持现有错误提示和空状态体验。

## Acceptance Criteria

* [ ] 进入银行卡池管理页面时不再显示顶部四张统计卡片。
* [ ] Orbitcard 用卡记录筛选区可输入关键词、选择套餐、卡片状态、充值状态并执行查询/重置。
* [ ] 后端返回筛选后的 `total`、`page`、`pageSize` 和 `cards`，分页总数与筛选结果一致。
* [ ] 翻页和刷新不会丢失当前筛选条件。
* [ ] 现有套餐绑定、恢复、同步卡片操作继续可用。
* [ ] `npm test` 通过。

## Definition of Done

* 实现前后端变更并完成测试/静态检查。
* 不改动与本需求无关的现有工作树变更。
* 更新必要的项目记录或规范说明。

## Out of Scope

* 不改变 Orbitcard 上游 API、卡片复用策略或数据库业务含义。
* 不新增复杂的日期范围筛选、导出功能或统计图表。
* 不删除银行卡列表本身，只移除其页面上方统计摘要。

## Technical Notes

* 页面结构：`public/admin.html`；交互：`public/admin.js`；样式：`public/admin.css`。
* API：`GET /api/admin/orbitcard/usage` in `server.js`。
* SQL 查询及记录聚合：`listOrbitcardUsage` in `mysql-store.js`。
* 现有分页渲染：`renderOrbitcardUsagePagination` in `public/admin.js`。

## Decisions

* 采用服务端筛选而非前端加载全部记录后过滤，避免数据量增长后页面和接口继续变长。
* 采用“一个关键词框 + 三个下拉条件”的紧凑筛选条；关键词覆盖最常用的卡与订单/账号定位场景。
* 卡片状态保留业务可读状态分组（可复用、使用中、已退役、上游已删除、已取消、未绑定套餐），充值状态按充值记录中是否包含成功/处理中/失败进行筛选。
