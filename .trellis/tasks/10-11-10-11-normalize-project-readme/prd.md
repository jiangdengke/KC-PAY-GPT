# 规范项目 README

## 目标

将项目根目录 `README.md` 重写为简洁、可信、可执行的项目入口文档，删除过时、重复、过度内部化和不适合公开展示的内容，并以成熟开源项目常见的信息架构组织内容。

## 范围

- 以当前源码、`package.json`、`docker-compose.yml`、`Dockerfile`、`.env.example` 和实际路由为准校准文档。
- 保留项目定位、核心能力、Docker 快速启动、本地开发、配置说明、安全边界、测试命令、目录结构和相关文档入口。
- 删除重复的长篇部署教程、过时套餐名称、已经移除的后台入口描述、默认密码提示、内部运营细节、供应商具体配置和无关联系方式。
- 不修改运行时代码、配置默认值、部署脚本或业务行为。
- 不在 README 中记录真实凭据、Token、Cookie、银行卡资料、生产地址或内部服务器信息。

## 验收标准

- README 章节顺序清晰，首次阅读者能完成 Docker 启动和本地开发。
- 命令、入口路径、套餐名称、脚本名称和本地链接与当前仓库实际内容一致。
- 不再出现 `product_activator.js`、`admin-login.html` 作为访问入口、Pro 5x/Pro 20x 作为新建套餐等已过时表述。
- README 本地链接存在，`git diff --check` 通过，现有项目测试全部通过。
- 改动只涉及 README 及 Trellis 任务记录，不部署、不修改业务代码。
