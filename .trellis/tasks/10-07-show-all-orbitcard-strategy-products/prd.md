# 展示全部 Orbitcard 开卡产品

## Goal

让后台“Orbitcard 开卡策略”展示上游返回的所有可用产品，避免将上游产品目录误认为只有两项；自动模式继续遵循现有优先级，手动指定产品时使用管理员选中的可用产品。

## Findings

* `/api/admin/orbitcard/products` 当前通过 `buildProductStrategyCatalog`，只保留渠道 3 优先产品和渠道 1 5556 产品。
* 上游产品目录可返回其他可用 BIN，例如 40005224、53211329、55565979，也可能按渠道字段或渠道分组返回产品。
* “同步卡台卡片”使用 `/getCardList` 读取已开出的卡，不等同于产品目录。

## Requirements

* 开卡策略产品下拉框展示所有可用、非 4002 禁用系列的上游产品。
* 保留自动模式的现有优先级：渠道 3 55565979，再按既有规则选择其他优先产品；不要让未分类产品改变自动模式候选顺序。
* 手动选择目录中的非优先产品后，保存接口必须接受该产品，后续需要新开卡时必须实际使用该产品。
* 产品无可用库存、缺少套餐价格或产品已失效时，继续由现有校验返回清晰错误。
* 不改变已存在卡片同步、复用、充值和 4002 禁用规则。

## Acceptance Criteria

* [x] 产品目录中包含截图所示的全部可用产品，而不是只显示两项。
* [x] 自动模式的首选产品和备用顺序保持现状。
* [x] 手动选择并保存未分类但可用的产品成功。
* [x] 新开卡任务能使用已保存的手动产品。
* [x] 4002 产品仍不展示且不能保存。
* [x] `npm test`、语法检查和 `git diff --check` 通过。

## Technical Notes

* 产品解析和自动排序：`orbitcard-client.js`。
* 后台产品接口和保存接口：`server.js`。
* 后台策略渲染：`public/admin.js`。
* 现有测试：`test/orbitcard-client.test.js`。

## Decision

采用“目录展示扩大、自动排序不变”的方案。展示层读取所有可用产品；自动选择仍调用原有优先级函数；手动指定路径单独允许已展示的可用产品。
