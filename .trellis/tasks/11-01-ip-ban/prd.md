# IP 封禁功能

## 背景

2026-10-31 起有人撞后台登录：11-01 一天 29 万次失败，几乎全部来自 `2a01:e5c0:2e15::/48` 的两万多个地址，另有 `109.120.178.219`。现有限流只能让请求返回 429，攻击流量仍持续打到服务。用户要求能把攻击者 IP 直接封掉。

## 需求

1. 管理员可以在后台手动封禁单个 IP 或网段（IPv4 / IPv6 CIDR），填写原因，选择时长（1 天、7 天、30 天、永久），并可随时解封。
2. 被封禁的来源访问任何页面和接口都直接返回 403；WebSocket 连接直接断开。
3. 自动封禁：同一来源（IPv4 单个地址，IPv6 按 /48）在后台登录或二次验证被限流后，15 分钟内仍被拒 20 次以上，自动封禁 7 天。
4. 防误伤：
   - 近 30 天有过成功登录的 IP 不会被自动封禁。
   - 不能手动封禁包含自己当前 IP 的网段。
   - 本机回环地址永不拦截。
   - 网段不能过大：IPv4 至少 /16，IPv6 至少 /32。
5. 列表显示每条封禁的命中次数、来源（手动/自动）、到期时间；登录日志里的 IP 可一键填入封禁表单。

## 实现约束

- 封禁表在运行时建表（`mysql-schema.sql` 未挂载进 app 容器），同时写入 schema 文件供新部署使用。
- 新增 `ip-ban.js` 时同步加入 compose 只读挂载，部署时用 `docker compose up -d app` 重建容器。
- 封禁规则缓存在内存，30 秒刷新一次，增删后立即刷新；命中计数批量写回。

## 验收

- 单元测试覆盖：CIDR 规范化与校验、IPv4/IPv6 匹配、过大网段与非法输入拒绝、自动封禁网段计算。
- 本地真实服务验证：手动封禁后请求返回 403、解封恢复；自动封禁触发；不能封自己的 IP。
- 上线后攻击网段被封，命中计数增长。
