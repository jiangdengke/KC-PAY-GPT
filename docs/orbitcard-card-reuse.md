# Orbitcard 卡片复用策略

## 配置

在后台「支付与资产 → Orbitcard 开卡策略」中，按 Plus、Pro 5x 和 Pro 20x 分别设置「一卡几冲」，可设为 1–20 次。默认值为 Plus 4 次、Pro 5x 和 Pro 20x 各 1 次。

设置只影响之后新开的卡。已有卡继续使用其用卡记录中的套餐和次数上限；修改设置不会重算已开卡片的首充金额或上限。

## 复用条件

新订单只会预留同时满足以下条件的已有卡：

- 上游卡片状态为 `ACTIVE`，且 BIN 不属于禁用的 4002 系列。
- 本地卡片状态为 `ACTIVE`，套餐与订单套餐相同，且未被其他任务锁定。
- 已成功使用次数小于该卡记录的复用上限，冷却时间已结束。

余额充足本身不代表卡片会被复用。达到上限、卡片已退役、处于冷却或锁定状态时，订单会转而尝试开新卡。

## 新卡首充

首充金额按所选产品的套餐价格、复用次数和产品保留余额要求计算，并满足产品最低首充金额；计算结果向上取整到 5 美元的倍数。降低复用次数会相应降低按套餐总金额计算的首充预算。

任务失败或结果不确定时，系统会退役该卡以避免再次扣款。只有确认没有发生扣款后，管理员才应在用卡记录中手动恢复尚未达到次数上限的卡片。

## 产品目录与卡片同步

“开卡策略”读取的是 Orbitcard `getProductCode` 返回的可开卡产品；“同步卡台卡片”读取的是 `getCardList` 返回的已开出卡片。产品目录中的多个 BIN 不代表本地已经存在同样数量的卡片。策略页面会展示所有可用且非 4002 的产品；自动模式仍按渠道优先级选择，手动指定产品时会使用管理员选中的有效套餐产品。

后台「Orbitcard 用卡记录」中的「同步卡台卡片」会查询卡台卡片列表，并逐张读取卡片详情后写入本地用卡记录。同步结果不会写入本地 Stripe「银行卡池」，也不会自动绑定套餐或改变已有卡片的使用次数。

同步完成后，需要在卡片操作列手动选择 Plus、Pro 5x 或 Pro 20x 并点击“绑定”。绑定会使用该套餐当前配置的复用上限；绑定后的 ACTIVE 卡会参与对应订单的自动选卡，未绑定套餐的卡不会参与。即使套餐复用上限为 1，已绑定且尚未使用的同步卡也可以作为该套餐订单的首次用卡。

同步会保存卡台返回的完整卡号、有效期、CVC、持卡人、卡台状态、产品代码和余额，因此该功能仅允许通过后台二次认证的管理员接口调用。若 API Key 没有敏感卡资料权限，卡片仍会登记，但页面会提示该卡没有同步到完整资料。
